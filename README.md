# ARVID DALI Center

Интеграция Home Assistant для DALI-шлюзов **Sunricher** на собственном транспорте: discovery,
шифрование, MQTT. Работает вместо штатной `dali_center` и переносит внутрь HA всё, что раньше
жило в приложении вендора — управление, события, именование, группы, пусконаладку.

> **Установка через HACS:** Интеграции → ⋮ → «Пользовательские репозитории» → добавить URL
> этого репозитория, тип «Integration». Затем «ARVID DALI Center» → «Скачать» → перезапуск HA →
> Настройки → Устройства и службы → «Добавить интеграцию».

## Что умеет

- **Свет** — лампы и DALI-группы как обычные `light.*`, включая **кросс-шлюзовые группы**
  (лампы на разных контроллерах, команда идёт веером на всех участников).
- **Датчики** — движение (`no_motion`/`motion`/`vacant`/`occupied`/`occupied_hold`) и
  освещённость в люксах; движение и люкс — одно устройство с двумя сущностями.
- **Кнопочные панели** — события вида `key3_click` с атрибутами клавиши и жеста, плюс триггеры
  устройств: в UI автоматизации выбираешь устройство и нажатие, без ручного разбора событий.
- **Автояркость (恒照)** — настройка контура поддержания освещённости, окна работы по расписанию,
  массовые операции через сервисы HA с адресацией по области.
- **Энергоучёт** — расчётный: `power_w` × кривая «яркость → мощность». Кривые задаются файлом
  и снимаются ваттметром на объекте (`tools/curves.example.yaml`).
- **Здоровье** — инкрементальный сбор ошибок (оффлайн, залипшие состояния) с живой подпиской.
- **Пусконаладка** — мобильная карточка: скан шины, именование по шаблону, карта
  «DALI-адрес → проектное имя» для переезда действующего объекта, раздача областей и ярлыков.
- **Автопусконаладка** — генератор плана (группы, области, автояркость, панели) по проектной
  таблице объекта и самодостаточный скрипт применения.

## Состав

| Каталог | Что внутри |
|---|---|
| `custom_components/arvid_dali_center/` | сама интеграция |
| `www/arvid-dali-panel.js` | панель управления (Lovelace-карточка) |
| `www/arvid-dali-commissioning.js` | мобильная карта пусконаладки |
| `blueprints/` | заготовки автоматизаций (например, клавиша панели → автояркость) |
| `tools/` | автопусконаладка объекта, кривые мощности, вспомогательные скрипты |
| `tests/` | тесты чистой логики (stdlib, HA не нужен): `python3 -m unittest discover -s tests` |

Карточки кладутся в `/config/www/` и подключаются ресурсами Lovelace
(`/local/arvid-dali-panel.js?v=1`). Развёртывание на объекте по шагам —
[`tools/README_OBJECT.md`](tools/README_OBJECT.md).

## Требования

- Home Assistant 2024.1 или новее;
- DALI-шлюз Sunricher в одной сети с HA (обнаружение по multicast, связь по MQTT);
- зависимости ставятся автоматически: `cryptography`, `paho-mqtt`.

## Принципы, по которым это написано

Два правила выведены разбором реальных отказов на объектах, и код их держится:

1. **Удаление в реестрах Home Assistant — мягкое.** Запись уезжает в корзину вместе с именем,
   `entity_id`, областью и ярлыками и воскресает по тому же `unique_id`. Поэтому «сделать как
   новое» означает **сбросить к шаблону**, а не удалить.
2. **Память контроллера ≠ физика.** Кеш шлюза (`searchDev exited`, `readGroup`, `readDev`) — это
   его собственная память, а не состояние шины. Истина существования — только физический скан;
   адресация — по идентичности (`devSn`), а не по адресу или индексу, потому что они протухают.

Отсюда же общий подход: **программа не решает деструктивно**. Спорные ситуации остаются видимыми
(осиротевшие записи, зомби, расхождения сверки), а разбирает их человек.
