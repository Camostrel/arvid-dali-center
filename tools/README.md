# Автопусконаладка объекта — `import_project.py`

Генератор скрипта пусконаладки: по нормализованной проектной таблице (parquet) + конфигу объекта
выдаёт **один самодостаточный файл** `apply_<объект>.py`, который на боксе Home Assistant создаёт
DALI-группы, привязывает автояркость и кнопочные панели, назначает HA-пространства (area).

Документ самодостаточный — для встраивания в агрегатор. Внутренняя версия (со ссылками на законы
проекта) — `docs/IMPORT_PROJECT.md`.

---

## 1. Два слоя и кто что делает

```
СЛОЙ 1 — генерация (машина коллеги / агрегатор)      СЛОЙ 2 — применение (бокс HA)
  data/normalized/*.parquet                            apply_<объект>.py
  + config_project.yaml                                        │
        │  import_project.py emit --out <путь>                 │  python3 apply_...py --apply
        ▼                                                      ▼
  apply_<объект>.py  ──── файл отдаётся заказчику ────►  пишет на DALI-шину через WS API HA
```

| Кто | Что делает |
|---|---|
| **Агрегатор (слой 1)** | вызывает `import_project.py emit`, получает файл по пути из `--out`, **отдаёт файл** |
| **Пусконаладчик** | сам кладёт файл на бокс (`/config/tools/`) и запускает `--apply` |

⚠ **Агрегатор скрипт НИКУДА не заливает и на боксе не запускает.** Его задача — положить готовый
файл туда, где его заберут: `--out` **указывать явно** (путь выгрузки / папка обмена / отдача
пользователю на скачивание). Без `--out` файл ляжет рядом с генератором как `apply_project.py` —
для продакшена так делать не надо: имя должно нести объект, напр. `apply_school301.py`.

Файл — обычный текст (~22 КБ), передаётся любым способом; **зависимостей у него нет** (свой
WebSocket-клиент на stdlib), нужен только `python3` на боксе.

---

## 2. Требования (слой 1)

```bash
pip install pandas pyarrow pyyaml     # websockets НЕ нужен: emit работает offline, HA не требуется
python3 import_project.py emit --normalized <parquet-dir> --config config_project.yaml --out <путь>
```

Все фазы слоя 1 (`names`, `caps`, `plan`, `emit`) работают **без подключения к HA**.

---

## 3. Вход: нормализованный слой (parquet)

Каталог с `normalized_meta.json` (проверяется `schema_version == 3` — при несовпадении генератор
останавливается) и тремя файлами:

| Файл | Читаемые колонки |
|---|---|
| `devices.parquet` | `entity_id`, `entity_id_2` (второй сенсор пары движение/люкс), `addr_floor`, `addr_bus`, `addr_num`, `addr`, `kind` |
| `groups.parquet` | `group_id`, `lamps`, `sensors_il`, `panels`, `space_type` |
| `spaces.parquet` | `space`, `room_slug`, `floor`, `groups`, `general_light_entity`, `space_type` |

Два правила по данным:

- **`entity_id` берутся ГОТОВЫМИ** из parquet, генератор их не собирает и не переименовывает.
- **Адрес `X.Y.Z` (этаж.шина.номер) используется ТОЛЬКО для offline-расчёта бюджета** «сколько
  DALI-групп ложится на шину». Реальный адрес для команд скрипт берёт у живого шлюза по
  `entity_id` — короткий адрес DALI волатилен (перенумерация шины его меняет), полагаться на
  табличный нельзя.

Шина = пара (этаж, шина) = один DALI-контроллер. **DALI-групп на шину ровно 16 (0–15)** — частные
зоны и общие группы помещений делят этот бюджет; переполнение видно в фазе `plan`.

## 4. Фазы генератора

```bash
python3 import_project.py <фаза> --normalized <parquet-dir> [--config config_project.yaml]
```

| Фаза | Назначение | Вывод |
|---|---|---|
| `caps` | **что можно выбрать в конфиге для ЭТОГО объекта** — действия/цели клавиш, параметры автояркости, типы помещений, этажи, список помещений | JSON в stdout |
| `names` | чек-лист ожидаемых имён устройств по шинам — под что называть на пусконаладке | текст |
| `plan` | offline-раскладка: группы по шинам + бюджет, автояркость, панели, area, **все несостыковки** | текст |
| `emit` | сгенерировать `apply_<объект>.py` с вшитым планом | файл по `--out` |

Порядок для UI агрегатора: **`caps` → пользователь заполняет конфиг → `plan` (показать отчёт и
предупреждения) → `emit` (отдать файл)**.

`caps` возвращает:

```json
{
  "panel_actions":  {"on": "включить", "off": "выключить", "toggle": "переключить",
                     "up": "плавно ярче (удержание)", "down": "плавно темнее (удержание)"},
  "panel_targets":  {"room": "...", "zone": "...", "zone1..zoneN": "...", "zone_by_order": "..."},
  "panel_max_keys": 8,
  "autobright_params": {"target_lux": "...", "tol": "...", "exclude_spaces": "...", "exclude_floors": "..."},
  "space_types_available": ["class", "korridor", ...],
  "floors_in_object":      [1, 2, 3],
  "spaces_in_object":      ["101_Вестибюль", ...]
}
```

Полезный флаг: `--space <подстрока>` — собрать скрипт **на одном помещении** для пробного прогона
(нумерация групп при этом остаётся такой же, как у полного объекта, — пробный прогон не разойдётся
с боевым).

## 5. Конфиг объекта (`config_project.yaml`)

Параметры отсюда **вшиваются в сгенерированный скрипт**. Токен HA в конфиг не кладётся никогда —
только через переменную окружения при запуске.

```yaml
ha:
  url: "ws://localhost:8123/api/websocket"   # адрес по умолчанию в скрипте (переопределим --ha-url)

general_groups:
  create: true               # делать ли реальную DALI-группу «всё помещение» (ест слот из 16)
  skip_if_single_zone: true  # помещение из одной зоны → общая = зоне, слот не тратим

areas:
  assign_general: true       # HA-area назначаем ТОЛЬКО общим группам; area ищется в HA ПО ИМЕНИ = space

autobrightness:
  by_space_type:             # автояркость получают только перечисленные типы помещений
    class:      { target_lux: 400, tol: 50 }    # luxRange = target ± tol
    recreation: { target_lux: 300, tol: 50 }
  exclude_spaces: []         # исключения по подстроке имени: ["105_Актовый"]
  exclude_floors: []         # исключения по этажам: [2, 3]

panels:
  layout:                    # любая клавиша 1..8 задаётся явно; 'rest' — все незаданные выше
    1: { press: "on",     hold: "up",   target: "room" }
    2: { press: "off",    hold: "down", target: "room" }
    rest: { press: "toggle", target: "zone_by_order" }
```

⚠ **Значения `on` / `off` — обязательно в кавычках.** YAML читает голые `on`/`off` как булевы
`true`/`false`, и действие клавиши молча превратится в мусор. Если агрегатор генерирует YAML
машинно — квотировать все строковые значения действий.

**area создаёт агрегатор, мы только назначаем.** Скрипт ищет area в HA по точному имени = `space`;
если такой area нет — печатает предупреждение и пропускает назначение (ничего не создаёт).

## 6. Что делает сгенерированный скрипт (слой 2)

Запуск на боксе:

```bash
export HA_TOKEN="<long-lived token HA>"
python3 apply_school301.py                        # DRY-RUN по умолчанию — только показывает
python3 apply_school301.py --apply                # применить
python3 apply_school301.py --apply --only panels  # одна фаза: groups | areas | autobright | panels
python3 apply_school301.py --apply --force        # пересоздать группы, даже если HA их уже знает
python3 apply_school301.py --apply --pace 1.0     # пауза между записями, сек (умолч. 0.3)
python3 apply_school301.py --ha-url ws://<IP>:8123/api/websocket   # если localhost недоступен
```

**Идемпотентность** (важно для агрегатора — скрипт можно перезапускать):

- **Группы** пропускаются, если HA уже знает группу тем же составом. Удалили группу в интерфейсе —
  пересоздастся; изменили состав в проекте — пересоздастся.
- **Автояркость и панели** HA-сущностей не имеют → применяются **каждый раз** (идемпотентно:
  снять старое + записать новое). Это не ошибка и не дубль.
- Состояние **не опрашивается у контроллера** — только у HA. Опрос контроллера флудит DALI-шину.

**Подтверждение каждой записи** — скрипт не печатает «OK» вслепую:

| Метка | Значение |
|---|---|
| ✅ подтверждено | шлюз подтвердил запись **и** перечитка показала ожидаемое (состав группы / luxRange / цель клавиши) |
| ⚠ без сверки | запись прошла, но перечитка не совпала — возможен прогрев памяти контроллера, перепроверить |
| ❌ НЕ подтверждено | шлюз не ответил даже после повторов — разбираться (связь/питание/адрес) |

**Про время выполнения.** Скрипт пишет ячейки контроллера, каждая запись — несколько обменов с
DALI-шиной, поэтому «одна панель» ≠ «одна команда»:

| Что | Обменов с шиной |
|---|---|
| одна DALI-группа | 3 (очистка слота + запись состава + перечитка) |
| одна привязка автояркости (датчик→группа) | 4 (разворот группы в лампы + снятие старого + запись + перечитка) |
| **одна привязка клавиши** (клавиша × жест) | 3–5 (перечитка ячейки + снятие старого, если было + запись + перечитка; для `toggle` ещё команда режима) |

Панель на 5 клавиш, где у двух задано и нажатие, и удержание, даёт **7 привязок ≈ 30 обменов** —
она идёт заметно дольше автояркости на те же помещения. Это нормальный ход, а не зависание.
Массовая запись временно нагружает шину — на время прогона ручное управление светом лучше не
трогать; `--pace` разгружает шину, пропорционально удлиняя прогон.

## 7. Ограничения

🔴 **Автояркость блокирует создание групп.** Если на объекте уже работают контуры поддержания
освещённости, DALI-шина занята постоянно, и создание групп отклоняется шлюзом («шина занята»).
Проверено на железе: так же ведёт себя и родной DALI Center — это свойство контроллера, а не
инструмента. Первый прогон на чистом объекте проходит (группы пишутся до автояркости), но
**повторный прогон требует: снять автояркость → создать группы → вернуть автояркость**.


- **Плавное диммирование по удержанию** (`up`/`down`) — кодировка помечена как уточняемая на
  железе. ✅ означает «цель привязалась к клавише», но не «жест отработал» — это проверяется
  нажатием на реальной панели.
- **DRY-RUN не читает текущее состояние автояркости и панелей** (у них нет сущности в HA) —
  показывает «будет применено», а не «уже так». Истинная картина — только при `--apply`.
- **Area назначается только существующим** в HA (поиск по имени = `space`).
- Клавиши сверх физического количества у панели пропускаются с предупреждением.
- Панели больше 8 клавиш и смешанные раскладки пока не поддержаны.

## 8. Быстрая проверка без объекта

В комплекте синтетический мини-объект (3 группы / 8 ламп / 3 датчика / 1 панель на 5 клавиш):

```bash
python3 import_project.py plan --normalized sample_mini
python3 import_project.py caps --normalized sample_mini
python3 import_project.py emit --normalized sample_mini --out /tmp/apply_mini.py
```

Ни одна из команд не требует HA и ничего не пишет на железо.
