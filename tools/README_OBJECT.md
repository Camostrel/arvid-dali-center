# Что положить на объекте, чтобы заработали КАРТА ИМЁН и АВТОПУСКОНАЛАДКА

> 📋 **Пошаговый план работ на объекте — docs/PLAN_COMMISSIONING.md.** Здесь — что куда
> положить; там — в каком порядке действовать и чем пользоваться.

> Памятка для развёртывания на новом боксе (новый HAOS). Всё, что ниже, кладётся руками один
> раз. Пути указаны от корня конфигурации Home Assistant — того самого `/config`, который
> видно в аддонах **File Editor** и **Studio Code Server**.

## Куда что положить

```
/config
├── custom_components/
│   └── arvid_dali_center/          ← САМА ИНТЕГРАЦИЯ (весь каталог из репозитория)
│
├── www/
│   ├── arvid-dali-panel.js         ← панель управления
│   └── arvid-dali-commissioning.js ← карта пусконаладки (карта имён + запуск плана)
│
├── arvid_namemap/
│   └── voronezh_name_map.csv       ← КАРТА ИМЁН объекта («адрес → проектное имя»)
│
├── arvid_curves/
│   └── curves.yaml                 ← кривые мощности драйверов (яркость % → ватты)
│
└── tools/
    ├── apply_voronezh.py           ← СГЕНЕРИРОВАННЫЙ план (группы + области)
    ├── run_apply.sh                ← обёртка: запуск плана в фоне + журнал
    └── arvid_apply.conf            ← токен долгого действия HA (заполняется руками)
```

Каталогов `arvid_namemap`, `arvid_curves` и `tools` на чистом боксе нет — создайте их.

## Пошагово

### 1. Интеграция и карточки

- `custom_components/arvid_dali_center/` — целиком;
- `www/arvid-dali-panel.js` и `www/arvid-dali-commissioning.js`;
- **перезапустить HA** (интеграция подхватывается только при старте);
- добавить ресурсы Lovelace (Настройки → Панели управления → Ресурсы):
  `/local/arvid-dali-panel.js?v=1` и `/local/arvid-dali-commissioning.js?v=1`.
  ⚠ При каждом обновлении файла меняйте число в `?v=` — иначе браузер и приложение отдадут
  из кеша **старый** код. На этом уже обжигались: карточка слала устаревший запрос, и
  области не проставлялись.
- добавить шлюзы объекта через Настройки → Устройства → Добавить интеграцию.

### 2. Карта имён

- положить CSV в `/config/arvid_namemap/` (имя любое, вкладка покажет список файлов);
- вкладка **«Карта»** в карточке пусконаладки появляется, только если файл там есть;
- ⚠ **сначала СКАНИРОВАТЬ шину** каждого контроллера: карта сшивается с живым сканом, до
  скана сопоставлять не с чем.

Порядок: скан → «Карта» → выбрать файл → проверить сопоставление → «Применить». Имена и
области ставятся вместе; у датчика одним действием именуются обе роли (движение + освещённость).

### 3. Токен для автопусконаладки

```
# /config/tools/arvid_apply.conf
ha_token: eyJhbGciOi…
```

Токен создаётся в HA: профиль (клик по имени внизу боковой панели) → низ страницы →
«Токены долгосрочного доступа». Образец файла — `arvid_apply.conf.example`.

⚠ Переменная окружения не подойдёт: `shell_command` в HA выполняется **без шелла**, и
`HA_TOKEN=… python3 …` он принимает за имя программы.

### 4. Запуск плана из карточки

В `configuration.yaml`:

```yaml
shell_command:
  arvid_import_apply: "sh /config/tools/run_apply.sh {{ script }} {{ args }}"
```

После правки — перезапуск HA. Дальше: карточка → вкладка «Карта» → экран **«План»** →
вписать `apply_voronezh.py` → «Проверить (dry-run)» → «Применить» → **«Журнал»**.

Прогон идёт **в фоне** (216 групп — это 6–8 минут), потому что HA обрывает команду через
60 секунд. Кнопка возвращает управление сразу, ход работы виден в журнале
`/config/tools/apply_voronezh.log`. Повторный запуск блокируется, пока идёт предыдущий.

**Что видно во время прогона** (кнопка «Журнал», обновляется сама раз в 2 с):

- полоса и «12 из 216» — счётчик `[k/M]` печатает сам скрипт;
- разбивка: `✅` подтверждено · `⚠` записано, но сверка не совпала · `❌` не подтверждено ·
  `=` HA уже знает такую группу (повторный запуск продолжает с места, а не переделывает всё);
- кнопка **«Остановить»** — прогон прерывается **между группами**, а не посреди записи (создание
  группы это `delGroup` + `addGroup`, обрыв между ними оставил бы группу удалённой). Последняя
  строка журнала скажет `⛔ ПРОГОН ОСТАНОВЛЕН` или `✅ ПРОГОН ЗАВЕРШЁН`.

⚠ Скрипт `apply_*.py` должен быть сгенерирован версией **1.2.69 или новее** — только такие умеют
мягкую остановку. Если в журнале нет строки «мягкая остановка поддерживается», карточка
предупредит при нажатии «Остановить».

### 5. Кривые мощности (энергоучёт)

`/config/arvid_curves/curves.yaml` — таблица «яркость % → ватты», снятая ваттметром на
объекте (образец с методикой — `curves.example.yaml`). Перечитывается кнопкой в панели
(Энергия → «Перечитать кривые»), рестарт не нужен. Без файла считается по встроенным кривым.

## Порядок работ на объекте

1. Развернуть интеграцию и карточки, добавить контроллеры.
2. **Отсканировать** каждый контроллер.
3. Применить **карту имён** (имена + области).
4. Ярлык `ba_area_light` общим группам — экран «Группы», кнопка «Только общие».
5. Запустить **план**: группы → области.
6. Автояркость и привязки кнопок — вручную (в плане они намеренно выключены).

⚠ **Автояркость блокирует создание групп.** При работающих контурах шина занята, и `addGroup`
отклоняется (`statusBus: занята`) — это не дефект инструмента, родной DALI Center падает так
же. Если автояркость уже разлита: снять → создать группы → вернуть.

## Что проверить, если не работает

| Симптом | Причина |
|---|---|
| Нет вкладки «Карта» | нет файла в `/config/arvid_namemap/` |
| Карта пустая, всё «нет на шине» | контроллер не отсканирован |
| «Применить» — ошибка сервиса | не прописан `shell_command` или не перезапущен HA |
| Скрипт пишет «нужен токен» | нет `/config/tools/arvid_apply.conf` или пустой `ha_token` |
| Журнал пуст | прогон не запускался; проверьте, что `run_apply.sh` лежит в `/config/tools` |
| Журнал стоит на месте, а прогон идёт | старый `run_apply.sh` (без `python3 -u`) — обновите файл |
| «Остановить» пишет «pid занят другим процессом» | прогон уже кончился, номер занял чужой процесс — трогать не будем |
| Группы не создаются, «шина занята» | включена автояркость — снять на время |
| Карточка ведёт себя как старая | не сменили `?v=` у ресурса Lovelace (кеш браузера) |
